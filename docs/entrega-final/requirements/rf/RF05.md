# RF05 — Registrar pagamentos

**Tipo:** Requisito funcional
**Status:** ✅ Implementado
**Atores:** Administrador

## Descrição
O sistema deve permitir registrar pagamentos de mensalidades.

## Implementação
- Schema: tabela `pagamentos` com `aluno_id` (FK), `data_pagamento`, `data_vencimento`, `valor`, `status` (ENUM `Pago`/`Pendente`/`Atrasado`), `referencia_mensal` (YYYY-MM), `metodo_pagamento` (ENUM), `observacoes`. Restrição `UNIQUE (aluno_id, referencia_mensal)` impede duplicar mensalidade — ver [`sql/01_schema.sql`](../../../../sql/01_schema.sql).
- API: `POST /api/pagamentos` em [`server.js`](../../../../server.js), `adminOnly`. Duplicata vira HTTP 400 explícito ("Pagamento já registrado para este aluno neste mês").
- Validação: `requireFields(['alunoId','valor','dataPagamento','referenciaMensal'])` via [`lib/validators.js`](../../../../lib/validators.js).
- Frontend: [`public/js/pagamentos.js`](../../../../public/js/pagamentos.js) — auto-preenche valor com base no plano do aluno.

## Testes
- API: [`tests/api.test.js`](../../../../tests/api.test.js) — bloco "PAGAMENTOS" (POST, duplicata, filtro por aluno) + [`tests/api.extra.test.js`](../../../../tests/api.extra.test.js) (validação 400).
- SQL: [`sql/04_tests.sql`](../../../../sql/04_tests.sql) — UNIQUE de duplicata mensal.

## Sequência (QUADRO 7)
Implementa o diagrama de sequência do docx: Administrador → Sistema → BD → Sistema → Administrador, com confirmação de sucesso.
